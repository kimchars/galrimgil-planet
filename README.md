# 🪐 갈림길 행성 — 20대 분기점 시뮬레이터

> 20대의 분기점을 **정보로 읽지 말고 미리 살아보는** 시뮬레이션.
> 모든 기본 갈림길은 통계청·교육부·한국고용정보원 등 **공개 통계**를 근거로 만들었다.

## 흐름
1. 시작: 이름·전공 계열·학년·관심 분야 → 학년에 따라 시작 질문이 다름
2. 행성 위 캐릭터 앞에 **분기점 질문**이 뜨고, 갈 수 있는 갈림길이 번호로 펼쳐짐 (키보드 1~9)
3. 번호를 고르면 캐릭터가 그 길로 걸어가고 **행성이 굴러감** → 결과: 📊 근거 통계(출처 링크) / 얻는 것·잃는 것(해석) / 📖 1년 뒤의 장면(AI 서술)
4. 앞의 선택에 따라 다음 질문이 달라짐 (예: 군 복무 → "전역 후" 질문, 어학연수 휴학 → 일 경험 질문 건너뜀). 결과가 갈리는 선택은 "붙었다면 / 길어진다면"을 골라 둘 다 체험 가능
5. **갈림길 지도**(마인드맵): 전체 분기점 + 지나온 길 + 다른 루트. 지나온 질문을 누르면 그 시점으로 되돌아가 다른 길을 살아봄 (이전 루트는 다른 색 궤적으로 행성에 남음)
6. **내 고민 추가**: 데이터에 없는 고민을 적으면 AI가 갈림길을 만들어 끼워 넣음 (통계 근거 없음 배지)
7. **엔딩 리포트**: 살아본 루트 비교, 마주친 분기점·확인한 통계 수, 안 가본 분기점

## 실행
```bash
npm install && npm run dev          # http://localhost:5173  (서버 없이도 예시 장면으로 끝까지 동작)
cd server && npm install && cp .env.example .env   # ANTHROPIC_API_KEY 입력
node server.js                       # http://localhost:8787  → AI 장면·AI 갈림길 활성화
SINGLE=1 npm run build               # 단일 파일 배포용 빌드
```

## 데이터 (`src/data/forks.json`)
- 분기점 15개 · 선택지 51개 (스펙 분기점: 자격증·공모전 포함), 각 수치에 출처(sources) 연결
- 출처: 2026·2024 경제활동인구조사 청년층 부가조사(통계청), 2024 고등교육기관 졸업자 취업통계(교육부·한국교육개발원), 2023 임금근로일자리 소득(통계청), 창업기업 생존율(중기부, 2020), 고용동향브리프 2026-5(한국고용정보원)
- `gains`/`costs`는 통계가 아닌 해석 → 화면에 "해석" 배지. "전역 후" 분기점의 선택지는 해석만 있음
- 대기업/중소기업 소득은 전 연령 평균(2023), 창업 생존율은 2020년 기준

## 도착지 추천 (`src/lib/jobs.ts`)
- 선택지마다 `gives` 스펙 태그(정보처리기사, SQLD, 공모전, 코딩테스트, 석사…)가 있고, 루트에서 모은 태그를 직무 6개의 요구조건과 규칙으로 매칭
- 점수 = 요구조건 충족 가중 비율(요구·전형 3, 가점 2, 우대 1). 합격 예측이 아님
- 근거: 공무원 전산직 가산점(정리 글), 국민건강보험공단 전형(정리 글), 삼성 채용 공식 페이지, 데이터 자격증 정리 글, AI 엔지니어 실제 공고 1건. 백엔드는 공고 수집 전(추정 배지)
- 엔딩에서 부족한 요구조건 → 채울 수 있는 분기점 안내 → "돌아가서 채우기"로 그 시점으로 되돌아감

## v4: AI가 질문·갈림길을 만들고 15개 직군 TOP 3를 추천
- **AI 모드(기본)**: 서버에 OpenAI 키가 있으면, 매 단계 AI가 지금까지의 선택·모은 스펙을 보고 다음 분기점 질문과 갈림길을 생성 (`POST /api/next`). 10개를 통과하면 `POST /api/recommend`로 15개 직군 중 TOP 3 + 근거·부족한 것·다음 행동 3개
- **근거 장치**: AI는 통계 수치를 직접 쓰지 못하고 근거 카드 ID(`s1`…)로만 인용 → 화면에는 실제 공개 통계가 표시됨. 선택지가 주는 스펙도 정해진 태그 목록 안에서만 고름. 추천은 규칙 점수와 함께 표시
- **대체 동작**: 서버·키가 없으면 첫 질문부터 기본 데이터셋(15개 분기점)으로 진행, 엔딩은 규칙 점수 TOP 3
- 결과 화면을 보는 동안 다음 질문을 미리 받아둬서 대기 시간을 줄임

### 실행 (OpenAI)
```bash
cd server && npm install && cp .env.example .env
# .env: LLM_PROVIDER=openai, OPENAI_API_KEY=sk-..., OPENAI_MODEL=gpt-4o-mini
node server.js            # 터미널 1
cd .. && npm run dev      # 터미널 2 → http://localhost:5173
```

### 채용공고 넣기 (`src/data/jobs15.json`)
- 15개 직군마다 `postings` 배열에 공고를 추가 (`postingTemplate` 형식, 원문 그대로)
- 서버는 요청마다 파일을 다시 읽으므로 서버 재시작 없이 반영됨. 화면의 "공고 반영 전" → "공고 n건 반영"
- `reqs`는 공고 반영 전 기본 요구조건(일반적 요구 역량 · 추정)으로 규칙 점수에 쓰임. 공고를 모은 뒤 빈도에 맞게 수정
